# Qaqeibo 仕様書 / 設計書

## 1. 概要

Qaqeiboは、個人の収入と支出を記録し、月ごとの家計の動向を確認するためのmacOSアプリです。家計を管理し、プログラムなどで自分でも分析したい利用者を対象とします。取引をラベルで分類し、月別一覧と内訳を表示します。記録はCSVで取り込み・出力できます。

## 2. 要件定義

### 2.1. 機能要件

- **F-01 取引の登録・編集・削除**　年月日、収支区分、ラベル、摘要、金額を登録・編集できます。摘要の入力欄は、支出では「用途」、収入では「収入元」と表示します。支出の用途を入力すると、過去に登録した用途から、ひらがなとカタカナを同一視して前方一致する候補を表示します。たとえば「せぶ」に対して「セブンイレブン」を提示します。候補を選ぶことも、自由に入力することもできます。削除前には確認を表示します。
- **F-02 月別一覧**　選択した暦月の取引を収入と支出に分け、日付の新しい順に表示します。起動時は当月を選択し、表示する年月を切り替えられます。
- **F-03 月別統計**　一覧と同じ月を対象に、収入・支出それぞれの合計、ラベルごとの合計と構成比を表示します。構成比の分母は、選択月の該当する収支区分の合計です。金額と割合を表で確認でき、構成比を円グラフで表示します。取引がない区分は合計を0円と表示し、円グラフの位置に空状態を表示します。
- **F-04 CSV出力**　全件、または月・収支区分・ラベルの条件に一致する取引をCSVに出力します。指定した条件はすべて適用します。保存先は「書類/Qaqeibo/output」とし、完了後は保存先をFinderで開けます。
- **F-05 CSV取り込み**　macOSのファイル選択ダイアログからQaqeiboのCSV形式に従うファイルを1つ選び、既存の記録に追加します。処理後は追加件数とスキップ件数を表示します。検証に失敗した場合は、修正に必要な行番号と理由を表示します。

### 2.2. 非機能要件

- **対応環境**　MacBookで動くmacOS専用アプリとします。最低対応バージョンは現行プロジェクト設定に合わせてmacOS 27.0.1とし、動作確認に使ったMacの機種とOSを記録します。
- **応答時間**　動作確認用のMacBookに取引1万件を読み込んだ状態で、月を切り替えてから一覧と統計の表示が更新されるまでを1秒以内とします。
- **データの扱い**　家計データはローカルに保存します。アプリ独自のログインは設けません。ファイルへのアクセスにはmacOSのApp Sandboxとユーザーが付与した権限を使います。
- **保守性とログ**　画面、取引のモデルと集計、CSVの読み書き、ファイル保存を責務ごとに分けます。取引の更新、月切替、集計、CSV入出力などの主要操作について、操作名・対象件数・所要時間・成否を記録します。ログに摘要や金額を含めません。

## 3. 画面・操作フロー

| 画面 | 主な表示と操作 |
| --- | --- |
| 月別一覧 | 年月切替、収入と支出の一覧、取引追加、統計とCSV操作への導線。取引を選択して編集・削除できます。 |
| 取引フォーム | 収支区分、日付、ラベル、摘要、金額を入力します。入力エラーは該当項目に表示し、保存に失敗した場合も入力内容を保持します。 |
| 統計 | 一覧と共有する選択月、収支区分ごとの合計、ラベル別の内訳と円グラフを表示します。 |
| CSV取り込み・出力 | 取り込みはファイル選択から開始します。出力は条件を指定して実行します。処理結果は操作元の画面で確認できます。 |

初回起動時に保存フォルダを選択します。設定後は月別一覧が開き、取引フォームで保存した取引を対象月の一覧と統計で確認できます。

## 4. データ・状態管理設計

### 4.1. 取引モデル

収入と支出を共通の取引として管理し、収支区分で識別します。各フィールドは必須です。

| フィールド | 定義 |
| --- | --- |
| `id` | 取引を一意に識別するUUID。アプリでの新規登録時に発行し、編集やCSVの入出力を通じて保持します。 |
| `date` | グレゴリオ暦の年月日。時刻・タイムゾーンを持ちません。月別検索と集計には記録された年月を使います。 |
| `type` | `income`（収入）または `expense`（支出）。 |
| `label` | 収支区分ごとの固定ラベル。初版の収入は「給与」「賞与」「その他」、支出は「食費」「住居費」「水道光熱費」「通信費」「交通費」「日用品」「娯楽」「その他」とします。 |
| `description` | 支出の用途または収入元。空白だけの入力は無効です。 |
| `amount` | 円単位の正の整数。収支区分にかかわらず正の値を保持します。 |

ラベルと収支区分は組にして扱います。月別一覧と統計は同じ取引データと選択月を参照します。

### 4.2. CSV形式

- 永続化、出力、取り込みに共通の形式を使います。ヘッダーは `id,date,type,label,description,amount` とし、UTF-8のコンマ区切りとします。日付は `YYYY-MM-DD`、金額は桁区切りや通貨記号のない10進整数です。ラベルには表で定義した名称を使います。
- コンマ、二重引用符、改行を含むフィールドは二重引用符で囲み、フィールド内の二重引用符は2つ重ねて表します。出力はBOMなし、改行はCRLFとし、取り込みではUTF-8のBOMの有無とLF・CRLFの両方を受け付けます。
- 取り込みではファイル全体を検証します。既存の取引または同じファイル内の先行行とUUID・内容が一致する行はスキップします。同じUUIDで内容が異なる行、形式に合わない行、無効な値がある場合は取り込み全体を中止し、既存の記録を保持します。行のエラーには該当するCSVレコードの開始行番号を表示します。

### 4.3. 永続化と失敗時の動作

- 初回にユーザーが「書類/Qaqeibo」フォルダを選択します。App Sandboxでユーザー選択ファイルの読み書きを許可し、セキュリティスコープ付きブックマークで、再起動後に同じフォルダへアクセスします。アクセスできなくなったときは理由を表示し、フォルダの再選択を案内します。
- 取引は `data/transactions.csv` に保存し、分析用のCSVは `output` に保存します。アプリ内の表示は保存済みの取引を基にし、登録・編集・削除・取り込みは、CSVの保存が成功してから一覧と統計に反映します。
- 更新時はCSVをファイル単位で置き換え、書き込みに失敗したときは元のファイルと表示データを保持します。起動時に保存済みCSVを読み込めない場合はエラーを表示し、原因が解消されるまでそのファイルへの書き込みを止めます。

## 5. システムアーキテクチャ・技術スタック

- SwiftとSwiftUIでmacOSの画面を実装します。円グラフにはSwift Charts、ファイル選択にはAppKitのファイル選択ダイアログ、ファイルの読み書きにはFoundation、ログにはOSLogを使います。
- 画面からファイル入出力を分離し、取引の検証、集計、CSVの変換を画面なしでテストできる構成にします。外部APIやクラウドサービスとの連携は初版の対象外です。

## 6. 開発・テスト計画

### 6.1. 開発順序

1. 取引モデル、保存先へのアクセス、取引の登録・編集・削除、月別一覧を実装します。この段階で取引IDとCSV形式を確定します。
2. 月別統計とラベル別の円グラフを実装します。
3. CSV取り込み・出力を実装し、画面からの一連の操作と応答時間を確認します。

### 6.2. テスト方針

- **ユニットテスト**　取引の入力検証、用途候補の前方一致、暦月の境界、ラベル別合計の総和と収支区分ごとの合計の一致、CSVの引用符・改行・重複・不正行を確認します。
- **結合テスト**　登録・編集・削除した取引が再起動後も正しく読み込めること、絞り込んだCSVを再取り込みすると元の取引が復元できること、同じCSVを再度取り込んでも取引が増えないこと、読込・保存・取り込みが失敗しても既存の記録を保持することを確認します。
- **動作確認**　「書類/Qaqeibo/mock」に用意したダミーデータで、フォルダ選択から再起動後のアクセス、月切替と集計の応答時間、統計の空状態、CSV出力後にFinderで保存先を開く操作を確認します。自動テストの書き込み先には一時ディレクトリを使います。
